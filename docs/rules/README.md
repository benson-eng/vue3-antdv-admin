# 專案規範總覽（Rules）

本目錄定義的是 **本專案唯一有效的工程規範**。
所有開發、轉換、重構、AI 協作，**必須以此為最高依據**。

---

## 一、文件定位與使用原則

### 這裡是什麼？

- ✔ 已實作驗證
- ✔ 已對齊 Vue2 行為
- ✔ 已在實際頁面中穩定運作
- ✔ 不照做一定會出問題

### 這裡不是什麼？

- ❌ 教學文件
- ❌ 操作流程（那是 SOP）
- ❌ 個人偏好
- ❌ 嘗試性想法

> **規範只負責定義「不能違反的邊界」。**

---

## 二、規範適用範圍

本規範適用於：

- Vue2 → Vue3 轉換
- 使用 Ant Design Vue 的列表頁
- 使用 DynamicTable / useTable 的頁面
- 管理後台（Admin 類型）頁面
  （具有查詢、列表、分頁、資料維護行為的系統管理頁）
- 使用 AI（Cursor / ChatGPT）輔助開發的情境

---

## 三、規範階段說明

本專案規範依專案生命週期分為兩個階段：

### 轉換期規範

- 適用於 Vue2 → Vue3 轉換與行為對齊階段
- 以「既有行為不被破壞」為最高原則
- 優先確保功能、互動與資料流完全一致

### 穩定期規範

- 適用於轉換完成後的長期開發與重構
- 在「行為等價」前提下，允許結構與寫法優化
- 目標為可維護性、可擴充性與架構品質

> 當所有主要頁面完成轉換，且不再需要以 Vue2 行為作為對齊依據時，即可視為進入穩定期。

---

## 四、核心工程原則（最高優先）

### 原則 1：行為對齊優先於寫法漂亮（轉換期原則）

- 在 Vue2 → Vue3 轉換階段，Vue3 的實作 **必須** 對齊 Vue2 的實際使用行為
- 不得在未經確認前，因語法或結構優化而改變既有行為

> 說明：
>
> - 本原則適用於「轉換與對齊階段」
> - 若 Vue2 的實作屬於歷史限制或非最佳解法，
>   **可在確認「行為等價」的前提下，改為 Vue3 較佳實作方式**
> - 行為等價需以實際畫面、互動與資料流驗證為準

---

### 原則 2：禁止使用「事後修補型解法」（所有階段適用）

以下類型屬於 **禁止模式（Forbidden Patterns）**：

- 以 MutationObserver 修 UI 行為
- 以 JS 強行同步 DOM 狀態
- 在 component 外層補 hack 解決內部結構問題

> 若需要這類解法，代表結構設計錯誤，必須回頭修正。

---

### 原則 3：結構錯誤不可用 CSS / JS 彌補（所有階段適用）

- UI 行為異常時，**優先檢查結構**
- 禁止以 sticky / overflow hack 掩蓋問題
- 禁止「看起來正常但結構錯誤」的實作

---

## 五、DynamicTable / Table 類型規範（總則）

### 搜尋區（Search Area）

- 搜尋區 **不得** 位於 table scroll container 內
- 搜尋區 **不得** 由 DynamicTable 自行處理 sticky 行為
- 搜尋區屬於 page-level 結構

---

### 表格本體（Table Body）

- table scroll 僅負責資料顯示
- 不可承載搜尋、工具列、狀態區塊

---

### 結構責任分離（強制）

- Page：負責 layout 與定位
- Search：負責查詢條件
- Table：負責資料呈現

---

## 六、AI 使用規範（非常重要）

### 使用 AI 前必須遵守

在使用 Cursor / ChatGPT 協助本專案時：

1. **必須先提供本規範內容**
2. 明確告知 AI：
   - 不得提出違反規範的解法
   - 不確定時需先詢問，不可自行假設
3. 若 AI 建議與本規範衝突，**以規範為準**

---

### 建議 AI 角色設定（可直接使用）

```text
你是本專案的前端工程協作 AI。
請嚴格遵守 docs/rules 內的所有規範。
不得提出違反規範的實作方式。
```
