# 本次 mock 整合與路徑切換說明

## 1. mock 模式開關與環境變數
- 新增 `VITE_ENABLE_MOCK` 環境變數（並同步新增 `types/env.d.ts` 定義與 `.env.development` 範例），讓開發環境可以顯式決定是否啟動 mock。
- `vite.config.ts`、`src/main.ts` 會讀取 `VITE_ENABLE_MOCK / VITE_MOCK_IN_PROD`，在 mock 開啟時停用 dev server 的 proxy、載入 `mocks/`，並透過 `mockSwitch.isMockEnabled` 讓其他模組共用開關判斷。
- `mockSwitch.ts` 提供 `resolveAdminSystemPath`，在 mock 模式時自動把原本 `/AdminSystem/api/...` 的呼叫導向 `/api/auth/...`，正式環境保持不變。

## 2. 請求與 mock 處理內容
- `src/utils/request.ts` 根據 mock 開關調整 `baseApiUrl` 與 `adminSystemApiUrl`，mock 模式下 axios 會保留相對路徑讓 Service Worker 可正常攔截。
- `mocks/_util.ts` 改為從 `mockSwitch` 拿 `isMockEnabled`，mock 模式時 `serverApi` 會強制使用 `/api` 作為 base 前綴，避免 handler 與實際請求不一致。
- `mocks/user.ts` 擴充 `serverApi('/auth/...')` + `/AdminSystem/api/...` 的 handler 避免 mock 與正式用戶登入資料落差，並調整 `loginHandler` 讓驗證碼欄位可選，保持錯誤訊息與原始流程一致。

## 3. API 端點與狀態同步
- 所有登入 / 取得使用者資訊 / 登出 / BackendKey API 現在由 `src/api/users.ts` 呼叫 `resolveAdminSystemPath('/AdminSystem/api/...')`，mock 模式會自動走 `/api/auth`，正式 API 仍是 `AdminSystem`。
- 透過 `mockSwitch.ensureMockPath` 也可於未來快速擴展其他 mock 路徑的對應關係，保持前端呼叫位置不需切換即可切換環境。

## 4. 測試與驗證建議
- 啟動開發伺服器前請確認 `.env.development` 的 `VITE_ENABLE_MOCK` 設為 `true`（正式建議為 `false`）。
- 使用登入畫面測試驗證碼、登入、使用者資料與登出流程，監控 Network 是否仍命中 `localhost:8088/AdminSystem/api/*` 且回應為 mock JSON。
- mock 模式下若要擴充更多 endpoint，可沿用 `mockSwitch.ts` 的映射表並在 `mocks/user.ts` 新增對應 handler。
