## 權限定義

### 權限碼格式

權限碼採用三段式命名規範：

```
類別:表單:存取
```

**格式說明：**
- **第一段（類別）**：模組分類，如 `system`（系統）、`member`（會員）、`netdisk`（網盤）
- **第二段（表單）**：功能/表單名稱，如 `role`（角色）、`user`（用戶）、`data`（資料）
- **第三段（存取）**：操作類型，如 `list`（查詢）、`create`（新增）、`update`（編輯）、`delete`（刪除）

**示例：**
```typescript
'system:role:list'      // 系統管理 -> 角色管理 -> 列表查詢
'system:role:create'    // 系統管理 -> 角色管理 -> 新增
'system:role:update'    // 系統管理 -> 角色管理 -> 編輯
'system:role:delete'    // 系統管理 -> 角色管理 -> 刪除
'netdisk:manage:download' // 網盤管理 -> 文件管理 -> 下載
```

### 超級管理員權限

超級管理員擁有特殊權限標識：

```typescript
perms: ['*:*:*']  // 萬用字元：所有類別:所有表單:所有存取 = 擁有全部權限
```

**說明：**
- `*`（第一段）：所有類別（system, member, netdisk...）
- `*`（第二段）：所有表單（role, user, data...）
- `*`（第三段）：所有存取操作（list, create, update, delete...）

## 權限驗證

### 核心函數

#### 1. `hasPermission(permCode: PermissionType): boolean`

**位置：** `src/permission/index.ts`

**功能：** 驗證當前用戶是否擁有指定權限

**實現：**
```typescript
export const hasPermission = (permCode: PermissionType) => {
  const permissionList = useUserStore().perms;

  // 1. 檢查是否為超級管理員（擁有所有類別:所有表單:所有存取權限）
  if (permissionList.includes('*:*:*')) {
    return true;
  }

  // 2. 精確匹配權限碼
  if (permissionList.some((n) => n === permCode)) {
    return true;
  }

  // 3. 支持萬用字元匹配（如 system:*:*, system:role:* 等）
  const [reqCategory, reqTable, reqAccess] = permCode.split(':');
  
  return permissionList.some((perm) => {
    const [category, table, access] = perm.split(':');
    
    // 逐段比對，* 代表匹配任意值
    const categoryMatch = category === '*' || category === reqCategory;
    const tableMatch = table === '*' || table === reqTable;
    const accessMatch = access === '*' || access === reqAccess;
    
    return categoryMatch && tableMatch && accessMatch;
  });
};
```

**功能說明：**
1. **超級管理員檢查**：如果權限列表包含 `*:*:*`，直接返回 true
2. **精確匹配**：檢查是否存在完全相同的權限碼
3. **萬用字元匹配**：支持部分萬用字元，如：
   - `system:*:*` - 系統類別下的所有表單、所有存取
   - `system:role:*` - 系統類別下角色表單的所有存取
   - `*:role:*` - 所有類別下角色表單的所有存取

**使用場景：**
- 在 `<script setup>` 中進行權限判斷
- 動態控制組件行為
- 複雜的權限邏輯處理

**示例：**
```typescript
import { hasPermission } from '@/permission';

// 判斷是否有新增權限
if (hasPermission('system:role:create')) {
  // 執行新增邏輯
}

// 根據權限顯示不同內容
const canEdit = hasPermission('system:role:update');

// 萬用字元匹配示例
// 假設用戶有 'system:*:*' 權限
hasPermission('system:role:create');   // true - 匹配 system 類別
hasPermission('system:user:update');   // true - 匹配 system 類別
hasPermission('member:data:list');     // false - 不匹配

// 假設用戶有 'system:role:*' 權限
hasPermission('system:role:create');   // true - 完全匹配
hasPermission('system:role:delete');   // true - 匹配所有 role 操作
hasPermission('system:user:update');   // false - 不同表單
```

#### 2. `v-auth` 指令

**位置：** `src/permission/index.ts`

**功能：** 自動移除沒有權限的 DOM 元素

**實現：**
```typescript
const vAuth: Directive = {
  mounted(el: Element, binding: DirectiveBinding<any>) {
    const bindVal = binding.value;
    
    if (bindVal == undefined) return;
    
    if (!hasPermission(bindVal)) {
      el.remove();  // 無權限則移除元素
    }
  },
};
```

**使用場景：**
- 需要完全隱藏無權限的按鈕或功能
- DOM 結構簡單的權限控制

**示例：**
```vue
<template>
  <!-- 無權限時按鈕不會渲染到 DOM -->
  <a-button v-auth="'system:role:create'">新增角色</a-button>
  
  <!-- 多個元素 -->
  <div v-auth="'system:user:delete'">
    <a-button danger>刪除用戶</a-button>
    <a-popconfirm title="確定刪除？">...</a-popconfirm>
  </div>
</template>
```

---

#### 3. `$auth()` 全局方法

**位置：** `src/permission/index.ts`

**功能：** 在模板中直接調用進行權限判斷

**註冊：**
```typescript
export default {
  install(app: App) {
    app.config.globalProperties.$auth = hasPermission;
    app.directive('auth', vAuth);
  },
};
```

**使用場景：**
- 在 `v-if`、`v-show` 中使用
- 與其他邏輯組合判斷
- 需要保留 DOM 結構但禁用功能

**示例：**
```vue
<template>
  <!-- 使用 v-if 控制渲染 -->
  <a-button v-if="$auth('system:role:create')" type="primary">
    新增
  </a-button>
  
  <!-- 使用 disabled 控制啟用狀態 -->
  <a-button :disabled="!$auth('system:role:update')">
    編輯
  </a-button>
  
  <!-- 組合邏輯判斷 -->
  <a-button 
    v-if="record.status === 'active' && $auth('system:user:delete')"
    danger
  >
    刪除
  </a-button>
</template>
```

---

### 三種方式對比

| 方式 | 使用位置 | DOM 行為 | 適用場景 |
|------|---------|---------|---------|
| `hasPermission()` | `<script setup>` | 由開發者控制 | 複雜邏輯判斷、動態行為控制 |
| `v-auth` | `<template>` | 無權限時移除元素 | 完全隱藏功能、簡單權限控制 |
| `$auth()` | `<template>` | 配合 `v-if`/`v-show`/`:disabled` | 靈活的模板權限判斷 |

### 1. 按鈕權限控制

```vue

### 2. DynamicTable 操作列權限

在 `columns` 配置中使用 `auth` 屬性：

#### 基礎用法（無權限則隱藏）

```typescript
const columns: TableColumnItem[] = [
  {
    title: '操作',
    dataIndex: 'ACTION',
    fixed: 'right',
    actions: ({ record }) => [
      {
        label: '編輯',
        auth: 'system:role:update',  // ← 無權限時隱藏按鈕
        onClick: () => edit(record),
      },
      {
        label: '刪除',
        auth: 'system:role:delete',
        popConfirm: {
          title: '確定刪除？',
          onConfirm: () => deleteRow(record),
        },
      },
    ],
  },
];
```

#### 進階用法（無權限則禁用）

```typescript
const columns: TableColumnItem[] = [
  {
    title: '操作',
    dataIndex: 'ACTION',
    actions: ({ record }) => [
      {
        label: '編輯',
        auth: {
          perm: 'system:role:update',
          effect: 'disable',  // ← 'disable' 表示無權限時禁用而非隱藏
        },
        onClick: () => edit(record),
      },
      {
        label: '刪除',
        auth: {
          perm: 'system:role:delete',
          effect: 'delete',  // ← 'delete' 表示無權限時隱藏（默認行為）
        },
        popConfirm: {
          title: '確定刪除？',
          onConfirm: () => deleteRow(record),
        },
      },
    ],
  },
];
```

**`auth` 配置說明：**

| 配置 | 類型 | 說明 |
|------|------|------|
| `auth: string` | `PermissionType` | 無權限時隱藏操作按鈕 |
| `auth: { perm, effect }` | `object` | 精細控制權限行為 |
| `auth.perm` | `PermissionType` | 權限碼 |
| `auth.effect` | `'disable' \| 'delete'` | `disable`: 禁用按鈕；`delete`: 隱藏按鈕 |

### 4. 條件渲染與邏輯判斷

```vue
<script setup lang="ts">
import { hasPermission } from '@/permission';

// 複雜權限邏輯
const canManage = computed(() => {
  const hasUpdate = hasPermission('system:role:update');
  const hasDelete = hasPermission('system:role:delete');
  return hasUpdate || hasDelete;
});

// 根據權限動態禁用
const handleDownload = (record: any) => {
  if (record.type === 'dir' || !hasPermission('netdisk:manage:download')) {
    message.warning('無下載權限或文件類型不支持');
    return;
  }
  // 執行下載邏輯
};
</script>

<template>
  <div>
    <!-- 多權限組合判斷 -->
    <a-space v-if="canManage">
      <a-button v-if="$auth('system:role:update')">編輯</a-button>
      <a-button v-if="$auth('system:role:delete')" danger>刪除</a-button>
    </a-space>
    
    <!-- 權限與業務邏輯結合 -->
    <a-button 
      :disabled="record.type === 'dir' || !$auth('netdisk:manage:download')"
      @click="handleDownload(record)"
    >
      下載
    </a-button>
  </div>
</template>
```

```typescript
export default {
  path: '/system',
  name: 'System',

    icon: 'SettingOutlined',
  },
  children: [

      meta: {
        title: '角色管理',
        perm: 'system:role:list',  // ← 路由級別權限控制
      },
    },
  ],
} as RouteRecordRaw;
```

在路由守衛中驗證（`src/router/router-guards.ts`）：

```typescript
router.beforeEach((to, from, next) => {
  const requiredPerm = to.meta.perm as PermissionType;
  
  if (requiredPerm && !hasPermission(requiredPerm)) {
    // 無權限訪問，跳轉到 403 頁面
    next({ name: 'ErrorPage', params: { code: '403' } });
  } else {
    next();
  }
});
```

### 5. 超級管理員與萬用字元處理

```typescript
// src/permission/index.ts

export const hasPermission = (permCode: PermissionType) => {
  const permissionList = useUserStore().perms;
  
  // 超級管理員擁有所有權限
  if (permissionList.includes('*:*:*')) {
    return true;
  }
  
  // 精確匹配
  if (permissionList.some((n) => n === permCode)) {
    return true;
  }
  
  // 萬用字元匹配
  const [reqCategory, reqTable, reqAccess] = permCode.split(':');
  return permissionList.some((perm) => {
    const [category, table, access] = perm.split(':');
    return (
      (category === '*' || category === reqCategory) &&
      (table === '*' || table === reqTable) &&
      (access === '*' || access === reqAccess)
    );
  });
};
```

**支持的權限格式：**
- `*:*:*` - 超級管理員，所有權限
- `system:*:*` - 系統類別的所有權限
- `system:role:*` - 系統類別下角色表單的所有操作
- `*:role:*` - 所有類別下角色表單的所有操作
- `system:role:create` - 精確權限
```

---

### 6. 萬用字元權限的使用場景

萬用字元權限適合用於：

#### 場景 1：模組級別權限
```typescript
// 給予用戶整個系統管理模組的權限
perms: ['system:*:*']

// 等同於：
perms: [
  'system:role:list',
  'system:role:create',
  'system:role:update',
  'system:role:delete',
  'system:user:list',
  'system:user:create',
  // ... 所有 system 類別的權限
]
```

#### 場景 2：功能級別權限
```typescript
// 給予用戶所有角色管理的權限
perms: ['system:role:*']

// 等同於：
perms: [
  'system:role:list',
  'system:role:create',
  'system:role:read',
  'system:role:update',
  'system:role:delete',
]
```

#### 場景 3：跨模組同類型權限
```typescript
// 給予用戶所有模組的查詢權限
perms: ['*:*:list']

// 等同於：
perms: [
  'system:role:list',
  'system:user:list',
  'member:data:list',
  'netdisk:manage:list',
  // ... 所有模組的 list 權限
]
```

#### ❗ 使用注意事項

**✅ 推薦使用：**
- 給予管理員整個模組權限：`system:*:*`
- 給予售後人員只讀權限：`*:*:list`, `*:*:read`
- 簡化權限配置，減少維護成本

**❌ 不推薦：**
- 過度使用萬用字元，導致權限過大
- 給予普通用戶 `*:*:*` 權限
- 在產品環境中不經評估就使用

### Q3: `v-auth` 和 `v-if="$auth()"` 有什麼區別？

**A:** 
| 特性 | `v-auth` | `v-if="$auth()"` |
|------|---------|------------------|

**推薦使用場景：**

### Q7: 前端權限控制安全嗎？

**A:** ⚠️ **前端權限控制僅用於 UI 優化，不能保證數據安全！**

**必須在後端進行權限驗證：**

```typescript
// ❌ 僅前端控制（不安全）
<a-button v-auth="'system:role:delete'" @click="deleteRole">刪除</a-button>

前端：<a-button v-auth="'system:role:delete'" @click="deleteRole">刪除</a-button>

```

**安全原則：**
1. 前端權限控制提升用戶體驗
2. 後端權限驗證保證數據安全
3. 兩者必須同時存在且一致

## 總結

### 核心要點

1. **權限來源**: 後端 API `/api/account/permissions`
2. **存儲位置**: Pinia Store `useUserStore().perms`
3. **驗證方式**: 
   - `hasPermission()` - 函數判斷（支持精確匹配和萬用字元匹配）
   - `v-auth` - 指令控制
   - `$auth()` - 全局方法
4. **權限格式**: `類別:表單:存取`
   - 精確權限：`system:role:create` = 系統類別:角色表單:新增存取
   - 萬用字元：`system:*:*` = 系統類別:所有表單:所有存取
   - 超級管理員：`*:*:*` = 所有類別:所有表單:所有存取
5. **匹配機制**: 支持三種匹配 - 超級管理員、精確匹配、萬用字元匹配

### 開發流程

```
1. 後端定義權限碼
   ↓
2. 添加到 src/permission/permCode.ts（提供 TS 提示）
   ↓
3. 在組件中使用 hasPermission() / v-auth / $auth()
   ↓
4. 後端接口添加權限驗證（必須！）
```

### 注意事項

- ⚠️ 前端權限僅用於 UI 控制，不能替代後端驗證
- ⚠️ 權限碼必須與後端保持一致
- ⚠️ 權限更新需要重新登入或手動刷新
- ⚠️ 使用 TypeScript 類型提示避免拼寫錯誤
